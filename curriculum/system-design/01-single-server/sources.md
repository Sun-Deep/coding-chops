# Sources

Status: none recorded, deliberately

This lesson explains fundamentals that no reference disputes. A client sends a
request and uses the response. A process is a running program. Memory is lost
when a process stops and persistent storage is not. Citing a specification for
any of that is decoration, not evidence, so nothing is recorded here.

That is a decision about this lesson, not a change to the standard. The rule in
`docs/video-production-standard.md` still holds: a claim that a viewer could
check, and be right to check, needs a reference before the script is approved.

Three claims in this episode sit closest to that line. If any of them is
questioned, or if a later lesson leans on them harder, they get entries here
first:

- The operating system may kill a process to reclaim memory. Specific to Linux
  and its OOM killer, with documented behaviour worth citing exactly.
- Requests arriving faster than a server finishes them form a queue. Standard
  queueing theory, and the claim the waiting-line visual rests on.
- Web applications commonly return data as JSON. RFC 8259.

## What to record when a source is added

- Link or bibliographic reference
- Claim supported
- Relevant section
- Access date

Do not use an AI-generated explanation as the sole source for a technical claim.
